# 用 ask 确认创作偏好

## 问什么，何时停

先看相册，结合当前请求填好能确定的内容，只问未知或确有冲突的字段。用户只给相册时，下列五组通常用两轮问完；不要把字段表原样丢给用户填写。

| 选择组 | 根据素材提出的建议 | 要取得的答案 |
| --- | --- | --- |
| 主题与美术方向 | 提议一个主题标题、页面风格与 3D 材质组合；已有设计稿优先 | 接受建议，或选择另一种气质；地点/故事不确定才追问 |
| 章节与重点 | 列出建议章节数、分组和重点照片，不猜真实行程 | 按推荐组织，或用户指定必须保留/排除的内容及顺序 |
| 照片与模型关系 | 默认混合“小照片同屏 + 照片转入模型” | 混合、偏同屏手账、或偏照片到空间的转场 |
| 展示设备 | 默认桌面 1280×800，不额外制作移动端 | 接受默认，或用户提出其他尺寸/设备需求 |
| 制作方式 | 默认推荐先看样板；同时给出减少等待和直接并行的选项 | 先看样板、样板自验后做完、直接全量并行（不做样板） |

第一轮优先主题/风格、章节与制作方式；第二轮只补仍未确认的照片关系与展示设备。用户已经给出其中任一选择时，删掉相应问题。问题与选项要结合本次相册，推荐项放第一项；允许自由文本或“其余你决定”。

制作方式的三个选项须讲清区别：“先看样板”让用户确认方向后扩展；“样板自验后做完”保留样板关卡但不等用户；“直接全量并行（不做样板）”在共享基础就绪后最大化并行，节省串行等待，但没有先用一屏确认风格的检查点。三种方式的逐页质量与验证要求相同。

设计参考不是必填素材；没有参考就根据相册提出风格组合。已有附件先查看，不要求重传。需要用户提供缺失图片/附件时用普通文字说明，不能把要求上传文件塞进只支持文本的 ask 工具。

不要询问：输出文件名、是否采用滚动叙事、Skill 路径、框架、打包方式或相机数值。标题可提议供用户修正；文件名由最终主题自动派生。

## 工具与阻塞语义

1. 查看当前工具定义。优先使用允许收集这些选择的原生 `ask` / `AskUserQuestion`；Codex 可使用 `request_user_input_async`。其他询问工具只有在当前模式和用途允许时才使用，不能为了问答强行切换模式。
2. 一次最多三个问题；同步工具返回真实答案后继续，异步工具等待新的用户消息。等待期间仅做不依赖答案的素材整理、资源对应与环境检查。
3. **未回复、默认选中、空返回和超时都不代表确认。** 不让限定为“可选问题”的工具承担必须等待的阻塞选择。没有合适工具时，用简短普通文字合并询问并停在相应制作步骤；告诉用户这些选择会决定作品风格/范围。
4. 用户明确“全部默认 / 都按推荐 / 你决定”后，将相应字段标为已授权，记录具体采用值并继续。已回答的问题不重复问；追问只处理会实质改变作品的冲突或缺口。
5. 初始问答完成后自主实现，不逐个审批颜色、材质或镜头。只有用户选择的样板确认、新的范围变更或真实外部授权需求才再停下。

## 样板确认

仅“先看样板”方式需要确认：先展示真实截图或可打开的样板页面，再问“这屏的模型质感、照片比例和整体风格是否按此继续？”。选项可为“按此继续”“调整后再看”，允许用户直接描述修改点。未认可时仅修改样板；认可后开始其余章节。

“样板自验后做完”仍须实际检查样板，但不再请求确认。“直接全量并行（不做样板）”跳过整个样板阶段，按主流程的共享基础检查后派发各页。用户明确“不做样板 / 地基打好直接并行”即采用第三种；仅说“不等我确认 / 自主完成”不自动等于跳过样板。用户中途明确更改时更新选择，不重复询问已授权项。

## 最小决策记录

在项目 `design.md` 保留主题、视觉方向、章节/照片映射、展示设备、制作方式及相应检查状态即可；不做样板时标记“不适用”，不伪造样板通过记录。禁止把对话完整复制为需求文档。修改已有成品时保留已确认项，只问此次改变涉及的未知项。
